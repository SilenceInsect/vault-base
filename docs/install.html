vault-base · 安装部署手册

从公开仓库 clone，落到用户级 common-skills-repo，再联接到各 IDE skills 目录。 本地 Vault + 共享金库（Redis / MySQL）按阶段推进；橙色步骤含外部依赖（运维 / DBA）。

真相源 ~/common-skills-repo/vault-base IDE Cursor / Claude / Codex 联接 事件后端 Redis LIST（无 Stream 时） 阶段数 8

安装流程总览

0 Clone→ 1 common 仓 + IDE 联接→ 2 物料清单→ 3 本地骨架→ 4 凭据与探测→ 5 共享库→ 6 清单 / 消费→ 7 验收

不要把 skill 只拷进某一个 IDE 目录当真相源。公共条目入库走共享 Redis/MySQL； 本机只维护一份 common 仓 + 多 IDE 联接。

阶段 0

Clone 公开仓库

产出：本机拿到脱敏后的 vault-base 源码

仓库公开、不含真实主机 / 密码 / 组私有目录。凭据与组清单只在本机生成。

0.1

Clone 到临时目录或直接进 common 仓

人工 
# 推荐：直接 clone 到用户级 common-skills-repo
mkdir %USERPROFILE%\common-skills-repo
cd %USERPROFILE%\common-skills-repo
git clone https://github.com/SilenceInsect/vault-base.git vault-base

# 或先 clone 再由脚本迁入（见阶段 1）
git clone https://github.com/SilenceInsect/vault-base.git
预期目录内有 SKILL.md、scripts/、docs/install.html（本手册）。
0.2

确认 Python

人工

需要可 import pymysql 的解释器（共享写入时）。记录其绝对路径，稍后写入物料清单。

python -c "import pymysql; print(pymysql.__version__)"
阶段 1

common-skills-repo + IDE 联接

产出：一份真相源 + Cursor/Claude/Codex 联接

真相源固定为 ~/common-skills-repo/vault-base（可用环境变量 COMMON_SKILLS_REPO 覆盖仓根）。 各 IDE 的 skills 目录只做 junction / 联接，禁止各拷一份再分叉。

1.1

初始化 common 仓并建 IDE 联接

可自动 
# 若已 clone 到 ~/common-skills-repo/vault-base，只需 link
set SKILL=%USERPROFILE%\common-skills-repo\vault-base
python %SKILL%\scripts\common_skills_repo.py init
python %SKILL%\scripts\common_skills_repo.py link --skill vault-base --ides cursor,claude,codex --backup-existing
python %SKILL%\scripts\common_skills_repo.py status --skill vault-base
IDE联接路径指向
Cursor~/.cursor/skills/vault-basecommon 仓
Claude~/.claude/skills/vault-base同上
Codex~/.codex/skills/vault-base同上
预期status 显示三端均为 LINK，目标同一绝对路径。
失败Cursor 目录被 IDE 占用无法改名 → 关掉打开该 skill 的标签页后重跑 link；或先 robocopy /MOVE 清空再 mklink /J。
1.2

业务 skill 声明接入

人工

name: your_business_skill

阶段 2

安装物料清单（引导提问）

产出：teams/<type>/<name>/install-inventory.yml

其他组成员安装时，skill 必须先引导提问补齐清单，再跑 env_ensure。 组目录默认 Git 忽略，不会随公开仓泄露。

2.1

init → missing → 逐项填写

可自动人工答 
set SKILL=%USERPROFILE%\common-skills-repo\vault-base
python %SKILL%\scripts\install_inventory.py init --id "<team-type>:<team-name>"
python %SKILL%\scripts\install_inventory.py missing --id "<team-type>:<team-name>"
python %SKILL%\scripts\install_inventory.py validate --id "<team-type>:<team-name>"

英文短名（清单内带中文注释）：

短名含义
local_only仅本地 Vault
local_then_shared先本地后共享（推荐）
shared_full直接共享全量
unknown / requested / done / blocked协调项状态
密码位置 清单里密码字段留空或写 <in_secrets>；真实密码只进 references/vault/_kb/secrets.local.json（已在 .gitignore）。
阶段 3

本地骨架

产出：Vault 目录 + 本地 Git + 依赖

不依赖共享 Redis/MySQL，可与 DBA 协调并行。

3.1

env_ensure + readiness

可自动 
set SKILL=%USERPROFILE%\common-skills-repo\vault-base
python %SKILL%\scripts\env_ensure.py
python %SKILL%\scripts\readiness_gate.py --fix --json
预期can_write_local=true；共享未就绪时 can_write_shared=false 且禁止一切共享写入。
阶段 4

凭据与环境探测

产出：secrets.local.json + 能力基线
4.1

填写本机凭据（脱敏模板）

人工勿入库 
# 从示例复制后填真实值 —— 真实 host/密码禁止提交公开仓
copy assets\secrets.local.json.example references\vault\_kb\secrets.local.json

{
  "sections": {
    "mysql_shared": {
      "host": "<SHARED_MYSQL_HOST>",
      "port": "3306",
      "user": "<USER>",
      "password": "<PASSWORD>",
      "database": "<SHARED_DB_NAME>"
    }
  },
  "redis": {
    "host": "<SHARED_REDIS_HOST>",
    "port": 6379,
    "db": 0,
    "password": ""
  }
}
4.2

只读探测

可自动 
python %SKILL%\scripts\env_probe.py --json

关注：Redis 是否支持 Stream、AOF / requirepass、MySQL 版本与字符集、同实例其他库数量（影响 DDL 评估）。

R4 身份回读 不能只判断「连接没抛错」；必须回读实际连接身份。连错身份却仍写共享 Redis，会导致发号/缓存污染。
4.3

外部协调项（X-*）

人工阻塞
编号事项说明
X-4建共享库权限无库则共享持久层无法落地
X-5DDL 影响面评估同实例若有业务库须评估
X-1Redis AOF不开则宕机可能丢事件
X-2Redis requirepass与客户端配置同步
X-7VCS 提交闸门防止 secrets 入库
阶段 5

共享库建设

产出：共享 schema 可用
5.1

执行 DDL（需 X-4 / X-5）

人工阻塞 
mysql -h <SHARED_MYSQL_HOST> -u <USER> -p \
  < assets/ddl_mysql57.sql

DDL 见 assets/ddl_mysql57.sql。库名以团队约定为准，写入清单与 secrets，勿把内网地址写进公开文档。
